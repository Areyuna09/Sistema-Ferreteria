FASE 1: MODULO DE REPORTES - Exportacion PDF y Excel
================================================================================

ARCHIVO: ReportsController.java
--------------------------------------------------------------------------------
PROBLEMA:
  El controlador era un STUB con datos de ejemplo hardcodeados. No estaba
  conectado al ReportDAO ni a los exportadores PDFExporter/ExcelExporter.
  Los botones de exportar no funcionaban.

CAMBIOS APLICADOS:

  [1] Reescritura completa del controlador
      - Se conecto con ReportDAO para consultas reales a la base de datos SQLite
      - Se integro con PDFExporter y ExcelExporter para exportacion funcional
      - Se agrego la clase interna ProductRow para el TableView con getters
        null-safe y formato de precio/total en pesos argentinos

  [2] Exportacion PDF funcional (handleExportPDF)
      - Dialogo FileChooser para seleccionar ubicacion de guardado
      - Conversion de datos a formato PDFExporter.ReportRow
      - Generacion del archivo PDF con Apache PDFBox
      - Apertura automatica del archivo al exportar (Desktop.open())

  [3] Exportacion Excel funcional (handleExportExcel)
      - Dialogo FileChooser para seleccionar ubicacion de guardado
      - Conversion de datos a formato ExcelExporter.ReportRow
      - Generacion del archivo Excel (.xlsx) con Apache POI
      - Apertura automatica del archivo al exportar (Desktop.open())

  [4] Validacion relajada (validateReportData)
      - Antes: exigia que currentProductsSummary no estuviera vacio
      - Ahora: permite exportar si hay estadisticas aunque no haya productos
        vendidos en el rango (caso valido cuando hay ventas sin items)

  [5] Manejo null-safe de datos
      - Metodos convertToPdfReportRows() y convertToExcelReportRows()
        manejan valores NULL de la base de datos sin lanzar NullPointerException
      - Campos: unit_price, variant_name, product_name, quantity, subtotal

  [6] selectedPeriod siempre asignado
      - Se asigna correctamente desde startDate en handleGenerateReport()
        para todos los tipos de rango (Hoy, Esta Semana, Este Mes, Este Ano)

  [7] Metodo openFile() agregado
      - Usa java.awt.Desktop.getDesktop().open(file) para abrir el archivo
        exportado automaticamente con la aplicacion predeterminada del sistema
      - Fallback: si Desktop no esta disponible, muestra mensaje informativo
        con la ruta del archivo generado

  [8] Navegacion mejorada (navigateTo)
      - Preserva el estado de la ventana (tamano y maximizado) al navegar
      - Caso especial para Login: reset a 1100x650 y centra en pantalla
      - Mantiene stage.isMaximized() al cambiar entre vistas


ARCHIVO: ReportDAO.java
--------------------------------------------------------------------------------
PROBLEMA:
  Las consultas SQL NO filtraban por status='completed', incluyendo ventas
  canceladas en los totales y estadisticas del reporte.

CAMBIOS APLICADOS:

  [1] Filtro AND status = 'completed' agregado a TODAS las consultas:

      - getStatsByDateRange()
        Estadisticas (total recaudado, cantidad ventas, promedio, maximo)

      - getProductSalesSummaryByRange()
        Resumen de productos vendidos por rango de fecha

      - getPaymentMethodTotalsByRange()
        Totales por metodo de pago (efectivo, tarjeta, transferencia)

      - getMonthlyStats()
        Estadisticas del mes actual

      - getProductSalesSummary()
        Resumen general de productos vendidos

      - getPaymentMethodTotals()
        Totales generales por metodo de pago

  NOTA: getDailySalesByRange() ya tenia el filtro correctamente.


ARCHIVO: PDFExporter.java
--------------------------------------------------------------------------------
CAMBIOS APLICADOS:

  [1] Helpers null-safe agregados
      - safeBigDecimal(Object): convierte de forma segura a BigDecimal
      - safeInteger(Object): convierte de forma segura a Integer
      - Reemplazan casts directos que podian lanzar NullPointerException

  [2] Lista de productos vacia
      - Cuando no hay productos vendidos en el rango, se muestra el mensaje
        "Sin productos vendidos en el rango seleccionado" en el PDF
        en lugar de una tabla vacia o error

  [3] ReportRow getters null-safe
      - getProducto(): retorna "N/A" si es null

      - getCantidad(): retorna 0 si es null
      - getPrecio(): retorna BigDecimal.ZERO si es null
      - getTotal(): retorna BigDecimal.ZERO si es null


ARCHIVO: ExcelExporter.java

CAMBIOS APLICADOS:

  [1] Helpers null-safe agregados
      - safeBigDecimal(Object): conversion segura a BigDecimal

  [2] Lista de productos vacia

FASE 3: MODULO DE CATEGORIAS - Mejoras UX
================================================================================

ARCHIVO: CategoriesController.java
--------------------------------------------------------------------------------
REFERENCIA: Se comparo con el proyecto de referencia en
  C:\wamp64\www\Sistema-Ferreteria (sin espacio, sin acento)

CAMBIOS APLICADOS:

  [1] Eliminacion del problema N+1 en tabla de subcategorias
      ANTES:
        subCategoryColumn usaba categoryDAO.findById(subcategory.getCategoryId())
        para obtener el nombre de la categoria padre. Esto ejecutaba una consulta
        SQL adicional POR CADA FILA de la tabla.
      AHORA:
        Usa subcategory.getCategoryName() que ya viene cargado desde el DAO,
        eliminando las consultas redundantes.

  [2] setupSearchListeners() agregado
      - categorySearchField.setOnAction() -> handleSearchCategory()
      - subcategorySearchField.setOnAction() -> handleSearchSubcategory()
      - Permite buscar presionando Enter en los campos de busqueda
        (antes solo funcionaba con el boton "Buscar")

  [3] setupCategoryComboBoxes() mejorado
      - StringConverter compartido para parentCategoryCombo y filterCategoryCombo
      - Antes: solo parentCategoryCombo tenia converter, filterCategoryCombo
        mostraba el toString() del objeto Category
      - Ahora: ambos combos muestran category.getNombre() correctamente

  [4] filterCategoryCombo.setOnAction() listener
      - Al cambiar la seleccion del combo de filtro en la pestana de
        subcategorias, se filtran automaticamente las subcategorias
      - Antes: habia que hacer clic en "Buscar" manualmente

  [5] loadSubcategories() respeta el filtro de categoria
      - Antes: siempre cargaba subcategoryDAO.findAll() ignorando la seleccion
      - Ahora: si filterCategoryCombo tiene un valor seleccionado, carga
        solo las subcategorias de esa categoria con findByCategoryId()

  [6] .active(true) en updates de categorias y subcategorias
      - Al actualizar una categoria: Category.Builder().active(true)
      - Al actualizar una subcategoria: Subcategory.Builder().active(true)
      - Previene que el registro quede con active=false (soft-delete accidental)
        al actualizar, ya que el Builder podria no tener valor por defecto

  [7] handleDeleteCategory() - eliminacion de doble loadCategories()
      - Antes: llamaba loadCategories() dentro del if (exito) Y tambien
        al final del metodo, causando doble recarga innecesaria
      - Ahora: solo recarga dentro del bloque de exito, junto con
        loadSubcategories() para actualizar contadores

  [8] Eliminacion de System.out.println de debug
      - handleSearchCategory(): 5 lineas de debug eliminadas
      - handleClearCategorySearch(): 1 linea de debug eliminada
      - Estos prints se usaban durante desarrollo y no debian estar en
        codigo de produccion

  [9] navigateTo() - preservacion de estado de ventana
      - Antes: stage.centerOnScreen() perdia el tamano y estado maximizado
      - Ahora: guarda wasMaximized, currentWidth, currentHeight
      - Crea Scene con dimensiones actuales
      - Restaura maximizado si estaba maximizado
      - Caso especial Login: reset a 1100x650, no resizable, centrado

  [10] loadCategories() mejorado
       - parentCategoryCombo usa lista independiente (no comparte referencia)
       - filterCategoryCombo usa lista separada con null como primer item
         representando "Todas las categorias"
